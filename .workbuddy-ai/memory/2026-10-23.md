## M2-22 — published course discovery (worker report filed, NOT accepted)

Claim `client-m2-22-published-course-discovery-20261023-01`, 16 allowed paths,
all implemented. Report filed; supervisor decides.

Decisions worth keeping:
- The publication migration deliberately has **no `unpublished` value**: "never
  published" and "published then withdrawn" must be indistinguishable to the
  public read, so both are `draft`. No backfill — nothing was published before
  this batch, so every existing row is `draft`.
- `publication_state` is NOT derived from `is_active`. `DELETE /api/courses/:id`
  already owns the archive flag; the public read requires BOTH, so archiving a
  published course withdraws it from discovery WITHOUT rewriting its publication
  record, and un-archiving restores exactly the prior state.
- Publication authority is exactly as wide as the accepted legacy course-edit
  authority (`courses.tenant_id = <selected tenant>`, any active teaching
  member). Inventing instructor-level narrowing would have been a new policy.
- The public catalog is a SEPARATE router at `/api/public` that consults **no
  principal at all** — proved by asserting each route's `stack` has exactly one
  layer (the handler) and that an authenticated caller gets a byte-identical
  body.
- `c.tenant_id` is deliberately not selected in the public projection; the tenant
  id comes from the joined `tenants` row, so an unresolvable tenant can never
  contribute an id. `description` is bounded in the SQL (`SUBSTRING(...,1,600)`).
- Search covers name+subject only, never description, so private wording in a
  description is not probeable. LIKE metacharacters escaped with `!`/`ESCAPE '!'`.

Gotchas hit this session:
- `UPDATE ... WHERE id=? AND tenant_id=?` legitimately contains `tenant_id=`, so
  a "does not write this column" assertion must be scoped to the **SET clause**
  and the qualifiers asserted separately.
- Express: `/courses/` (empty segment) collapses to the LIST route via the
  optional trailing slash; `/courses/../courses` matches no route at all. Both
  pinned as explicit tests rather than assumed.
- Client discovery controller: a duplicate `load()` must be refused **before**
  the search generation advances, otherwise the read that already owns the latch
  has its own reply dropped as superseded.
- Client discovery controller: a retired read must still settle the phase it set,
  otherwise a session change strands the page on "loading". `settleReadPhase` is
  guarded by `phaseOwner`, so a newer read is never disturbed.
- `classifyCourseFailure` maps only `An active tenant membership is required` to
  `denied`; a 403 `Forbidden` falls through to `error`. Rather than change
  accepted M2-02 classification, the publication path has its own
  `PUBLICATION_DENIED_MESSAGES` set.
- TS: `unknown` is not narrowed to `string | null` by a compound
  `x !== null && (typeof x !== 'string' || !RE.test(x))` guard — use a type
  predicate helper instead.
