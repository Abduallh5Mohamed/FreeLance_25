تاريخ العمل: **9 نوفمبر 2026**. استكمال مباشر للمهمة الكبيرة4، بعد BUILD-60، ضمن الخطة22. لا عودة إلى BUILD-45 المفتوح في IDE، ولا تشغيل لـOpenCode أو الجدولة.

## النتيجة للمستخدم

مسار جديد **`/teacher-workspace`** في قائمة المدرس يجمع اختيار مقرراته وحصصه، ملخص تجهيز الحصة، أدلة وسوم الكويز، ورحلة خطة الرجوع الأصلية. مدرس المقرر الحالي يستطيع استخدامها حتى لو لم يكن مالك المؤسسة. ملكية المؤسسة أو عضويتها وحدها لا تمنح مسؤولية أكاديمية، وأدمن تبويب وموظفو التشغيل لا يدخلونها.

متابعة جديدة للخطة المحفوظة تعرض نسختها الحالية وخطواتها والإكمال المسجل في مسار الدروس الجديد. الخطوة التي لم تعد متاحة تفقد عنوانها ومعرفها وحالة إكمالها في الرد. الخطة المسحوبة لا تعيد خطة أقدم. لا يُفترض بدء مذاكرة أو فهم أو انتهاء خطة من سجل الإكمال، ولا نكتب تقدمًا أو نمنح اشتراكًا.

إعادة استخدام الموسم تظل لمقدم الخدمة التعليمية الذي يملك المؤسسة، بعد المعاينة وتأكيد الحقوق الموجودين. أُضيف إثبات الهوية التعليمية الحية واستبعاد عضويات إدارة المنصة للمسار وللاسترجاع التاريخي. مدرس مقرر مستقل لا يحصل تلقائيًا على حق نسخ قوالب المؤسسة. لم نكرر محرك القوالب أو ننشئ نسخ محتوى إضافية.

## العقود والمعمارية

- `teaching-authority.ts`: دور teacher/instructor من الهوية والصف الحالي، عضوية تعليمية نشطة بالمؤسسة النشطة، حساب نشط غير موقوف، نسخة جلسة حالية، `center_account=0` وعدم وجود `admin_user_roles`. لا impersonation أو هوية staff أو billing-only. الدليل على اتصال معاملة القراءة/الحفظ نفسه.
- مسؤولية المقرر من `courses.instructor_id` مع tenant والمقرر النشط، لا من اختيار العميل أو `tenants.owner_user_id`. قائمة المقررات مفلترة بالمدرس، وقائمة الحصص تعيد إثبات المقرر قبل الأسماء. صفحات25 مع قراءة26 وكيرسور صريح، دون هوية طالب أو URLs أو محتوى أسئلة في الاختيارات.
- مسارات التحضير ومجموعاته وأدلته الأصلية، ومسارات roster/preview/review/save/withdraw/receipt الأصلية لخطة الرجوع، تستعمل الإثبات نفسه الآن. لم نفتح مسارات إعداد المحتوى المملوكة للمؤسسة للمدرس المستقل.
- GET `/api/tenants/me/catalog/teaching/courses`؛ GET `/teaching/courses/:courseId/lessons` تحت نفس البادئة.
- GET `/courses/:courseId/return-plan/follow-up/:enrollmentId` تحت نفس البادئة: إثبات المدرس ثم الطالب والقيد والمقرر والمجموعة/الفرع، فحص مخطط الخطط، رأس ونسخة حاليان فقط. الخطة النشطة تتطلب مخطط الحضور/التقدم الحالي من بوابة الرحلة الموجودة. حتى3 خطوات، وإثبات أهلية الدرس لكل خطوة قبل إظهار بياناتها. القراءة فقط ومعاملة تنتهي بـROLLBACK، وno-store في النجاح والفشل.
- لا استخدام لمحاضرة قديمة كمعرف درس catalog، ولا دمج سجلي تقدم. إكمال catalog مقروء من محركه الأصلي ولا تُنشئه الخطة.
- واجهة الاختيارات ذات parser صارم وحد25، وإلغاء وepoch وربط principal/session. مهلة25 ثانية تشمل parser والنقل الذي يتجاهل الإلغاء؛ فشل القراءة يخفي القائمة السابقة.
- تبديل المقرر والحصة مقفول أثناء حفظ/استرجاع خطة غير محسوم، بما فيه فشل تنظيف علامة عملية مؤكدة. استُخدمت رحلة الحفظ والإيصالات السابقة نفسها، لا محرك ثانٍ. لا إعادة كتابة تلقائية.
- المتابعة الجديدة تُخفى بعد60 ثانية أو إخفاء الصفحة، وبعد تغير الحساب/الاختيار أو فشل GET. التحديث صريح. إظهار الإكمال لا يعني إمكانية تسليم الفيديو أو الملفات المؤجلة.
- مسار React محمي بـAuthGuard و`course.manage`، مع منع المنصة الموجود. القائمة الجانبية لها تسمية واضحة لزر الطي، وselect الطالب تسمية ثابتة. تنسيق الصفحة يلف الأزرار والمحتوى داخل العرض المتاح.
