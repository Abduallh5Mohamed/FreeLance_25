# رحلات المنتج وشرط الموافقة قبل التنفيذ

**القرار الحاكم المحدث:** التسعير تدريجي للمدرس والسنتر؛ فوترة المؤسسة كل 30 يومًا مع حساب مدة فعلية بالثواني وتسوية، لا عمولة على الطلاب؛ محفظة السنتر وحده أو المدرس المستقل؛ خصم الاشتراك من المتاح ومهلة 4 أيام. المرجع [19 — القرارات المعتمدة](19-commercial-registration-wallet-agreement-ar.md)، والموافقة قبل التنفيذ في 18. الوثائق ليست دليل تشغيل.

هذه وثيقة تصميم للمنتج المستهدف، وليست إثباتًا أن الرحلات تعمل حاليًا. التفاصيل التالية تحتاج اعتماد المستخدم قبل تنفيذها. كل الوظائف في 17 ضمن النطاق؛ M1–M8 ترتيب بناء فقط.

## شرط حاكم: عرض العمل ثم الموافقة

قبل كل دفعة تنفيذ، حتى داخل مرحلة سبق اعتمادها، يكتب المنفذ في المحادثة: الهدف، السلوك قبل وبعد التغيير، المهام والملفات المتوقع تعديلها، أثر البيانات والخدمات، الاختبارات التي سيشغلها، ومعيار الانتهاء وأي استفسارات. ثم ينتظر جوابًا صريحًا من المستخدم:

- «نفّذ»: تنفيذ الدفعة الموصوفة فقط.
- «متنفّذش»: توقف عن الدفعة.
- «تعديلات»: عدّل العرض وأعد عرضه وانتظر اعتماد النسخة الجديدة.
- سؤال أو إجابة عن استفسار: لا تعد موافقة تنفيذ إلا إذا تضمنت تصريحًا واضحًا.

الموافقة على مرحلة كاملة لا تمنح موافقة تلقائية لكل دفعاتها. الصمت أو مرور الوقت ليسا موافقة. إذا ظهر تغيير جوهري في النطاق أو أثر البيانات، يوقف المنفذ العمل المتأثر ويعرض التغيير أولًا. يمكن قراءة الملفات لتجهيز العرض؛ تعديل الكود أو الوثائق غير المطلوبة صراحة، تشغيل الاختبارات والخدمات والمهاجرات، إنشاء commits، الدمج، النشر والدفع إلى remote يجب أن تكون ضمن عرض معتمد. كتابة هذه الوثيقة وتحديث روابطها معتمدان بطلب المستخدم الحالي. لا تطلب أو تعرض قيم الأسرار.

## رحلات محدثة وفق 19

### المدرس المستقل والسنتر

تحقق اتصال → اختيار نوع المؤسسة → إنشاء بروفايل وهوية ونطاق → عرض الاشتراك التدريجي و30 يومًا وشروط الخصم → checkout أو عرض خاص → تفعيل موثق → إضافة موظفين/مدرسين/فروع → مقررات ووحدات ودروس → أسعار شهر الطالب ومجموعات/جدول → نشر audience محدد لكل المحتوى → استيراد طلاب بمعاينة وإزالة ازدواج → تقييم وحضور وتقارير. لا ينشئ signup admin أو owner بمؤسسة موجودة. السنتر يدير محفظته ويحاسب مدرسينه؛ المدرس المستقل يدير محفظته.

### تسجيل الطالب

1. صفحة المدرس/السنتر تعرض المنشور فقط؛ اختيار المدرس/المقرر/المجموعة وOnline أو Offline.
2. اسم/هاتف/صف، شروط وخصوصية، OTP محدود أحادي الاستخدام؛ رقم قائم يستعمل نفس الهوية ولا ينشئ نسخة.
3. Online: سعر المدرس مثبت في order ثم checkout ثم تأكيد خادمي؛ تفعيل 30 يومًا، أو شراء مقدم ببداية مستقبلية معلنة.
4. Offline: طلب pending_approval بلا دفع مطلوب في التسجيل؛ مدرس/مسؤول مخول يراجع ويقبل أو يرفض بسبب. القبول لا يثبت التحصيل؛ وصول مدفوع أو مهلة محددة، وإلا حجب المحتوى.
5. Offline يقدر يدفع إلكترونيًا إذا المدرس فتح الخيار، أو نقدًا بإيصال. الدفع لا يغير النوع؛ عند مدرس آخر له تسجيل ونوع مستقلان.
6. دوراتي تعرض البداية والنهاية والمهلة/الدين والحالة؛ شروط drip والتتابع والتسجيل والنوع مفحوصة بالخادم لكل ملف/فيديو/امتحان/واجب/حصة.
7. هوية جزئية watermark وDRM وفق الجهاز والمزود، جودة منخفضة واستكمال، والتنزيل بسماح ودعم مثبت. لا وعد بمنع تصوير الشاشة.
8. الامتحان نسخة ثابتة وموعد خادمي ومحاولة محفوظة؛ MCQ يحسبه الخادم؛ المقال غير المصحح pending_review دون نتيجة نهائية، وعرض محاولة سابقة يستخدم الحالة نفسها. واجبات وملفات مفحوصة وتصحيح ونشر. **(قرار بشري 2026-10-19: "وشهادات بشروط" استُبعدت من النطاق الحالي — المنتج منصة مدرسين وطلاب مدارس لا منصة تخرّج/شهادات. مصدر مسار الشهادات وهجراته وبياناته التاريخية محفوظة غير محذوفة، وأُزيل التركيب العام فقط (`/api/certificates` لم يعد مُركَّبًا في `server/src/index.ts`)، ولا يُعدّ ذلك مانع إكمال لـ M1/M4. التفاصيل: `docs/streams/server/TEACHER-SCHOOL-PRODUCT-ALIGNMENT.md`.)**
9. live دخول موثق وحضور وإعادة اتصال لا تضاعف الحساب، وتسجيل للمكتبة بعد معالجة ونشر وaudience. الحضور الشخصي Offline يدوي/وسيلة معتمدة منفصلة عن دخول live.
10. parent link موثق وتفضيلات إشعار وQ&A ودعم. الطفل بلا هاتف يحتاج سياسة قبل التنفيذ، لا يدمج عدة أطفال في حساب هاتف واحد افتراضيًا.

### المحفظة والفوترة

pending → available بعد مصالحة المزود؛ الاشتراك يحجز من available عند استحقاقه قبل سحب جديد، ويحترم حجزًا قائمًا. نقص → خصم المتاح وطلب الفرق → مهلة 96 ساعة من الطلب → تنبيهات → عند عدم الدفع وقف قبول/تجديد طلاب ونشر جديد، مع بقاء كل الفترات المؤكدة المدفوعة الحالية والمستقبلية وإتاحة الدفع والتصدير والدعم. الدفع الصحيح يعيد الصلاحيات. مراجعة فاتورة: عدد ومدة فعلية، نسخة سعر، مقدم، تسوية، رصيد سابق/دائن؛ المبالغ المرحّلة لا تفوتر مرتين.

طلب سحب → تحقق وصلاحية ومراجعة مالية → حجز → تحويل بمرجع → نجاح أو تحرير الحجز مرة واحدة عند الفشل. طلب استرداد → قرار المحصل (مدرس أو سنتر) → توفير وحجز المبلغ → مزود → قيد عكسي وإشعار وتحديث الوصول. النقد ليس available؛ لا عمولة منصة ولا split داخل السنتر.

### الإدارة وولي الأمر

Super-admin MFA → tenants/flags/plans/offers → usage/financial reconciliation → tickets/moderation/appeals → impersonation بسبب ومدة وصلاحية ضيقة وشريط وسجل → suspend/restore وتدقيق. Financial officer يعتمد السحب دون تغيير الهوية/الاتفاق المالي بلا صلاحية. ولي الأمر دعوة خاصة وتحقق صلة → قراءة تقدم وحضور ودرجات منشورة لأطفاله فقط → opt-in WhatsApp/SMS وإلغاء وربط قابل للسحب. لا يتطلب عرض الطالب للولي عضوية موظف.
