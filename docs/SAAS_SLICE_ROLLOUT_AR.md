# شريحة SaaS الأولى: حالة التنفيذ والنشر الآمن

هذه الشريحة لا تعني اكتمال خطة SaaS كلها. تشمل فصل إدارة المدرسين عن التدريس، صلاحيات إدارية صريحة، مركز عمليات أولي، تهيئة tenant واشتراك منصة، دفعة منصة بمراجعة مسؤول مختلف، دعوة المالك، طلبات موافقة لتعديل رصيد الخدمات، حارس كتابة التدريس، وتجديد الاشتراك ودورة انتهائه.

## دورة اشتراك المدرس

1. ينشئ مسؤول مخول tenant وحساب مالك غير مفعل واشتراك `pending`.
2. تحدد الإدارة رقم هاتف المدرس وكلمة مروره عند إنشاء الحساب، لكنه يظل غير نشط. يضيف مسؤول مخول محاولة دفع بمفتاح idempotency ومرجع، ويتحقق مسؤول آخر من وصول المبلغ؛ عندها فقط يُفعّل tenant ويستطيع المدرس الدخول بهذه البيانات.
3. يبدأ التجديد بطلب اشتراك `pending` جديد. عند تحقق دفعه يبدأ من نهاية الفترة الحالية إن لم تنته، أو من وقت التحقق إن انتهت. لا تُرسل دعوة ثانية، ولا يُرفع تعليق tenant الإداري تلقائيًا.
4. مهمة المصالحة تحول الاشتراك إلى `grace_period` عند نهاية الفترة، ثم `expired` بعد 3 أيام؛ وعند اختيار الإلغاء بنهاية الفترة يصبح `cancelled`. حارس كتابة التدريس يفحص الاستحقاق وقت الطلب، لذلك لا يعتمد المنع على توقيت العامل وحده. حسابات `legacy_compat` لا يُفرض عليها اشتراك بأثر رجعي.

## ترتيب النشر

1. جرد قاعدة الإنتاج ونسخة احتياطية واستعادة تجريبية، ثم مراجعة المخطط الفعلي مقابل `server/migrations/20260921_saas_foundation.sql`. لا تستخدم ملف `payment_requests` القديم قبل إصلاحه.
2. طبّق migration الإضافية في بيئة تجريبية مماثلة ثم إنتاج؛ راجع عدد tenants والعضويات وتعارضات الهوية يدويًا. لا تنسب علاقات الطلاب/المحتوى المبهمة تلقائيًا.
3. انشر الخادم والواجهة مع `ALLOW_LEGACY_INSTRUCTOR_CREATION=false` و`ALLOW_DIRECT_SERVICE_CREDIT_ADJUSTMENT=false`. لا تفعّل `SAAS_LIFECYCLE_JOBS_ENABLED` قبل التأكد من وجود المخطط ومن صحة تواريخ الفترات.
4. عيّن أعضاء الإدارة صراحةً حسب الدور؛ لا يتحول موظفو `staff` تلقائيًا. اختبر تسجيل الدخول والأذونات لكل دور، وجرّب التهيئة/الدفع/المراجعة والتجديد على tenant تجريبي.
5. فعّل `SAAS_LIFECYCLE_JOBS_ENABLED=true` بعد التحقق. العامل يعمل عند بدء الخادم ثم كل ساعة ويستخدم قفل MySQL advisory لمنع معالجة الدفعة نفسها بالتوازي.

## ما لم يكتمل بعد

- ترحيل `tenant_id` لكل صفوف الطلاب والمجموعات والمحتوى وعزل كل واجهات القراءة والكتابة القديمة؛ الحارس الحالي يغطي بعض مسارات كتابة التدريس فقط.
- اشتراك الطالب الشهري، وسائل دفع المدرس، محاولات دفع الطالب والإثباتات الخاصة، الدفعة المقدمة، التسوية والإيراد؛ تبقى التدفقات القديمة كما هي إلى حين بناء البديل والتحويل التدريجي.
- إدارة دورات المهام والموافقات كاملة، التصعيد والتذكيرات والتقارير والتدقيق الشامل، ومراجعة كل مسارات المال والإدارة القديمة.
- اختبارات التكامل الموسعة للتنافس والترحيل والرجوع على نسخة من بيانات الإنتاج.

## حذف المدرس المؤقت

هذا وصف تاريخي لمسار حذف نهائي مؤقت أزيل من الـ API ولوحة الإدارة. إدارة الحساب تكون بالإيقاف والاستعادة مع الاحتفاظ بالبيانات وسجل التدقيق؛ لا يوجد زر أو مسار حذف نهائي للمدرس.

لا تنقل هذه الشريحة إلى الإنتاج على أنها إطلاق كامل لـ SaaS. التطبيق يظل بحاجة إلى feature flags وتحويل تدريجي واختبارات قبول الأدوار والتدفقات المالية على قاعدة مماثلة للإنتاج.
