## الهدف والسلوك قبل/بعد

قراءة المصدر Courses.tsx أثبتت: load مرة دون إبطال scope/session، حفظ يعتمد
React loading دون قفل متزامن، الحذف يغلق الحوار ويمسح الهدف في finally حتى
بعد الفشل، edit يضع اسم الصف course.grade في حقل ينتظر grade.id، وparseFloat
مع fallback0 يخفي الإدخال غير الصالح. إعادة التحميل بعد كتابة ناجحة ليست
مفصولة بوضوح عن نجاح الكتابة نفسها. هذه أدلة مصدر، لا ادعاء تجربة خدمات.

النتيجة: عرض تحميل/فراغ/خطأ مستقل، قراءة وكتابة مربوطة بالسياق الفعلي، منع
التكرار قبل render، حفظ المدخلات/هدف الحذف عند الفشل، نجاح مصدره الخادم،
ومعالجة فشل refresh بعد نجاح الكتابة دون تكرار الإنشاء. خريطة الصف تحفظ العقد
القائم الذي يخزن الاسم؛ لا تحويل schema إلى grade_id. التحقق العددي يمنع
NaN/Infinity والقراءة الجزئية الخاطئة دون تغيير سياسة السعر أو التسعير.

## العقد والأثر

GET /courses يعيد المقررات النشطة في سياق المستدعي وفق courseScope، وليس
إسقاطًا عامًا للنشر. POST يعيد201 Course وcreateCourse adapter يعيد id؛ PUT
وDELETE reject عند فشل الخادم؛ DELETE يؤرشف is_active ولا يحذف فعليًا.
grade حاليًا اسم، وليس id. requireTeachingWrite يحكم الكتابة؛ role محلي ليس
تصريحًا. المصدر server/src/routes/courses.ts وsrc/lib/api-http.ts:625–667.
ثبت التفاصيل الفعلية في تقرير العقد؛ لا تضف حقولًا/صلاحيات من التخمين.

لا أسعار جديدة أو checkout/OTP/entitlement أو نشر عام أو إعادة تصميم اشتراكات.
احتفظ بالحقول الصحيحة القائمة، وبلغ عن عقود ناقصة بدل اختراع ربط subscription
غير موجود في payload. هوية/اكتشاف عام C1–C4 ووحدات ودروس/drip من C5–C7 تحتاج
عقودًا/دفعات لاحقة؛ هذه الدفعة لا تدعي تنفيذها.

عند تشغيل المنتج تبقى الكتابات هي create/update/archive الحالية فقط. لا
migration أو نقل بيانات أو خدمة/DB/network/provider حي أو installs أو Git writes
أو commit/push/deploy. الاختبارات fixtures وtransport/storage محقونة فقط.

## المهام ومعيار الانتهاء

1. جرد scoped diff قبل التعديل، حفظ كل العمل الصحيح، وتثبيت العقد.
2. إصلاح العيوب المثبتة بأقل تعديلات كاملة، لا إعادة كتابة شاملة أو framework.
3. ربط guards فعلًا بالصفحة، مع session/scope/form-target lifetime عبر النجاح
   والفشل وfinally/dispose. الرد القديم لا يمسح نموذجًا جديدًا أو busy أحدث.
4. اختبارات إنتاج حقيقية: duplicate save/delete، reverse loads، session/target
   changes، failures+retry، mutation-success/refresh-failure، grade-name/id mapping
   والصف غير المتاح دون محوه صامتًا، null/invalid numeric، presentation errors
   دون اختراع status رقمي أو صلاحية محلية. RTL/labels من المكونات القائمة.
5. تشغيل الاختبارات المعزولة والجناح العميل المناسب وفحص frontend types؛
   baseline408 اختبارًا و11 خطأ خارج النطاق، لا الادعاء أن الكل نظيف.
6. checkpoint عند معلم حقيقي ثم تقرير وتوقف؛ القبول للمشرف، لا مرحلة جديدة
   أو مدة مصطنعة. عند429 توقف مرة بلا إعادة محاولة أو تبديل حساب/model.

WorkBuddy ينفذ أصلًا عبر MCP؛ Codex يراجع ولا يسحب المهمة نيابة عنه. لا عامل
بديل أو تحرير claim بالعمر. لا ادعاء native run/session ID غير متاح أو liveness
من claim. الجدولة ربع ساعة للمشرف، فحص WorkBuddy الساعي متوقع لا مضمون؛ نهاية
الدفعة توقف الجدولة، انتظار الفحص الطبيعي لا يوقفها.
