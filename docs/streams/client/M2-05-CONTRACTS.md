## 2. قيد النقل الموثّق (لم يُلتف عليه ولم يُختلَق)

النقل المشترك يرمي رسالة الخطأ من الخادم **بدون** رمز الحالة
(`src/lib/api-http.ts:69-89`). لذلك:

- التصنيف في الواجهة يتم **بالرسائل الموثّقة فقط** (`error`)، ولا يُستنتج أي رمز
  حالة رقمي. حقول `code` (`TOKEN_EXPIRED`/`SESSION_REVOKED`/`TENANT_SUSPENDED`/
  `STUDENT_SPACE_REQUIRED`) ورمز الحالة يُهملان في النقل، فلا تُستخدم وحدها للتصنيف:
  رمز وحده يبقى **خطأ قراءة قابلًا لإعادة المحاولة** (فشل مُغلق)، لا صلاحية
  مُختلقة.
- أي رسالة غير موثّقة (بما فيها فشل الشبكة و«Failed to load tenant profile»)
  تبقى **خطأ قراءة قابل لإعادة المحاولة** مع عرض رسالتها الحقيقية — الفشل
  المُغلق هو السلوك المقصود، لا حالة صلاحية مُختلقة.
- 409 «Select an instructor workspace first» يُصنَّف «لا توجد مساحة عمل مُصرّح
  بها» لأن جوهرها غياب مساحة مرتبطة، ولا يُعرَض كتعطيل حساب.

## 3. هوية مؤكدة من الخادم فقط

- البطاقة تعرض `business_name` و`subject_type` (عند وجوده فقط) و`status`
  كبيانات وصفية — **لا** تُعادل حالة المساحة بالدفع أو الأهلية للمقررات.
- لا اسم مستخدم محلي، ولا DTO فوترة، ولا هوية احتياطية، ولا مُحدّد مستأجر من
  العميل بأي شكل. غياب أو تلف المظروف = خطأ، لا هوية مُلفّقة.
- لا شاشة أو مسار جديد: التكامل داخل `InstructorDashboard.tsx` القائمة على
  `/instructor`؛ استدعاء الانتقال الحي هو `getMyTenantProfile()` نفسه الذي
  تُختبره الحزمة.

## 4. أعمار العملية في الواجهة (`src/features/tenant/profile.ts`)

- **request**: كل تحميل يقدّم جيلًا رتيبًا؛ الرد المقلوب أو المستبدل لا يُلتزم
  أبدًا، و`finally` القديم لا يفك قفل تحميل أحدث (كل `finally` يحرر بتذكرته).
- **duplicate suppression**: قفل فوري قبل أول `await`؛ نقرة إعادة محاولة
  ثانية أثناء القراءة لا تصل إلى النقل.
- **session/scope**: الهوية القانونية تُعاد قراءتها عند **الدخول وعند إكمال**
  كل قراءة عبر قارئ M2-02 المقبول (`readCourseSessionPrincipal`). حدث الجلسة
  يُبطل كل الجاري و**يمسح الهوية الخاصة قبل** بدء القراءة الجديدة. وتغيير الرئيس
  **المرصود بلا حدث** (تسجيل خروج/تبديل نطاق صامت أو استبدال جلسة من الخادم)
  يُعتمد أيضًا: يُبطل الجيل القديم، وتُمسح الهوية/الخطأ/`loading`، ويُحرَّر القفل
  فتصبح إعادة المحاولة/القراءة الجديدة قابلة للاستخدام — بدل إسقاط الرد وترك
  هوية قديمة وحالة تحميل معلّقة. لذلك A → B → A لا تخلط هويات، والرد القديم لا
  يُلتزم في جلسة أحدث، و`finally` القديم لا يحرر قفل قراءة أحدث.
- **dispose**: إلغاء التركيب يُسقط كل ردود الجاري ويعيد الحالة الأولية
  (`idle` + لا هوية + لا خطأ)؛ متحكّم مُزال لا يبدأ شيئًا جديدًا ولا يستجيب
  لأحداث الجلسة.
- **logout**: بلا رئيس ⇒ تُمسح الهوية وتُحاول القراءة الصادقة التي تفشل
  مُغلقة (401/«No token provided» أو «Invalid token» أو «Session revoked» ⇒
  `unauthorized`).

## 6. ما لا تُثبته هذه الحزمة

- لا رسم DOM فعلي ولا اختبار متصفح (لا jsdom مُثبّت والتثبيت ممنوع): إثبات
  دورة حياة الزر والحالة يتم عبر المتحكّم الحقيقي وحاجز الجلسة، لا через
  RTL/render.
- لا شبكة حية ولا قاعدة بيانات ولا خدمات: كل طلب في الاختبارات وهمي
  (mocked transport)، وسلوك الخادم مُستمد من عقده والمقبول سابقًا.
- لا ادعاء أداء أو زمن استجابة أو قابلية توسع: لم تُقَس؛ الاختبارات تثبّت
  **عدد** الطلبات (واحد لكل تحميل، وكتم المكرر) لا زمنها.
- تمييز النتائج عبر حالة HTTP غير ممكن من العميل (قسم 2)؛ أي تمييد مستقبلي
  يتطلب تغيير عقد النقل المشترك — خارج هذا النطاق.
