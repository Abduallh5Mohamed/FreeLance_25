## الدفعة المعروضة M2-01 — عقود ورحلات الدعوة والانضمام والمساحات

### المشكلة الحالية المثبتة بالمصدر

- `JoinInstructor`: تحميل الدعوة يعتمد token لكنه لا يبطل الرد القديم ولا
  يمسح بيانات الدعوة السابقة؛ submit/reset يعتمدان React busy دون قفل متزامن.
- `TenantInvitation`: التفعيل يعتمد busy في العرض دون قفل فوري، والحقول تحتاج
  labels/معالجة لوحة مفاتيح واضحة مع حفظ المدخلات عند الفشل.
- `StudentSpaces`: لا حالة تحميل صريحة؛ قد يظهر «لا توجد عضوية» قبل اكتمال
  القراءة. اختيار المساحة يبدل التوكن ثم ينتظر تحميل الطالب؛ فشله يمكن أن
  يترك بيانات مساحة سابقة بجانب الهوية الجديدة. لا اخترع تراجعًا إلى توكن
  قديم ولا أستنتج نجاح التفعيل من حالة العميل.

هذه قراءات مصدر لا تجربة متصفح/خدمات، ولا إعلان بأن كل الفروع أعيد إنتاجها.

### النتيجة المطلوبة

دعوة/انضمام/اختيار مساحة بخادم مصدر الحقيقة: طلب واحد لكل عملية، لا بيانات
أو نجاح من رد قديم، حالات تحميل/فراغ/رفض/انتهاء/خطأ منفصلة، حفظ النماذج عند
الفشل، ومساحة لا تعرض هوية سابقة بعد تبديل التوكن. لا تغيير سياسة pending
approval القائمة إلى Online checkout أو OTP دون عقد خلفي معتمد.

### الملفات المقترح السماح بتعديلها فقط بعد الاعتماد

- `src/pages/JoinInstructor.tsx`
- `src/pages/TenantInvitation.tsx`
- `src/pages/StudentSpaces.tsx`
- `src/features/enrollment/workflows.ts` — وحدة صغيرة فقط إذا احتاجتها الرحلات
  لفصل orchestration القابل للاختبار عن React، لا framework عام.
- `src/tests/m2-enrollment-workflows.test.ts`
- `src/tests/m2-tenant-invitation.test.ts`
- `docs/streams/client/M2-CONTRACTS.md`

قراءة العقود فقط: دوال الدعوات/الانضمام/المساحات في api-http، session-events،
ومسارات الخادم student-enrollment/tenant-invitations/auth وما يلزم غير السري.
لا تعديل api-http أو الخادم/الراوتر/الحزم/schema/config في هذه الدفعة. الاحتياج
الفِعلي لمسار آخر يعرض أولًا، ولا يوسّع العامل claim بنفسه.

### عقود يجب تثبيتها قبل تعديل السلوك

طريقة/path/body/query، سياق principal/tenant، الحقول والأنواع، null/empty،
حالات401/403/404/409/410/429/503 الفعلية، expiration، ومعنى نجاح طلب الانضمام.
افحص الردود من source؛ لا تجعل رمزًا مقترحًا ردًا منفذًا. افصل العقود المتاحة
من مواصفات19 غير المبنية (OTP/Online payment/30-day entitlement).

ثبّت دليل بوابة M1 من الاختبارات/التقارير المتاحة دون خدمات. إغلاق039 محلي
لا يكفي لإثبات API/private-file/video/job/socket isolation لكل المنصة. إذا
غاب دليل لتدفق يعتمد عليه التنفيذ، سجل النقص وحدوده ولا تدّع اكتمال M2؛ لا
تضيف اختبارات خدمات أو تغييرات خادم من هذه الدفعة.

### أثر البيانات والخدمات

لا migrations أو تغيير مخطط أو نقل بيانات، لا خدمات/DB/network/provider حي،
لا installs أو نشر/commit/push. الكود يستخدم API الحالي فقط. عند تشغيل المنتج
تظل الكتابات هي طلب انضمام/استرجاع كلمة المرور/تفعيل دعوة/اختيار مساحة القائمة
حاليًا؛ لا أثر تسجيل/دفع جديد. الاختبارات تستخدم fixtures غير سرية وtransport
وstorage وclock محقونة دون وصول حقيقي. لا تسجل كلمات مرور أو توكنات/دعوات.

### الاختبارات والانتهاء

- اختبار دوال الإنتاج التي تستخدمها الصفحات، لا نسخ المنطق داخل الاختبارات.
- تكرار قبل render، فشل ثم إعادة محاولة،401/403/expired، تغيير الدعوة A→B→A،
  ردود متعاكسة، unmount، وتبديل مساحة ثم فشل تحميل الهوية.
- labels/focus/keyboard وRTL وفق المكونات القائمة؛ لا ادعاء DOM/browser دون دليل.
- اختبارات العميل السابقة المناسبة مع الجديدة؛ tsc frontend كامل مع فصل11
  خطأ قديم خارجي. استخدام runtime والأدوات الموجودة، لا إضافة dependencies.
- تقرير الملفات الفعلية، العقود/failures غير المحسومة وأدلة قبل/بعد؛ قبول Codex
  مطلوب. النهاية تحقق هذه المعايير لا زيادة عدد الاختبارات أو استهلاك الوقت.

## مبادئ المراجعة المعمارية والأداء

- Modular monolith ضمن الموجود: DTO/validation/permission وorchestration وواجهة
  وحدود transport واضحة؛ تجنب services وهمية أو نقل ملفات شامل.
- احتفظ بإصلاحات M1 دون إعادة كتابة/تنسيق شامل. اعزل المنطق القابل للاختبار
  بأصغر وحدة إنتاج فعلية، لا helpers لا تستعملها الصفحات.
- سجل عدد الطلبات ومسارات التكرار؛ لا per-row fetch أو unbounded Promise.all،
  ولا cache يخفي تغير الصلاحيات. إلغاء/إبطال التحميلات عند تغيير السياق.
- query count/pagination/payload/transactions والفهارس تراجع مع مالك الخادم في
  الدفعة المختصة. لا ادعاء high-scale أو latency من unit tests أو source وحده.
- لا microservices/cache/queues جديدة بلا حاجة مثبتة، ولا تغيير مالي من أجل
  تبسيط UI. لا نقل ملكية المقرر أو tenant من مدخلات غير موثوقة.

## التشغيل بعد اعتماد الدفعة

Codex يجهّز task محلية بمعرف جديد وallowedPaths واعتماد scopeHash ثم WorkBuddy
يسحبها من MCP بحساب التطبيق. لا نعيد تدوير مهام M1 أو فك claims بمرور الوقت.
claim/checkpoint/report في سياق أصلي مستمر مع إيصال حقيقي؛ لا أسرار في ملفات.
لا يبدأ عامل بديل قبل توقف المالك. إن ظهر429/حاجز أداة توقف مرة بلا تحايل.

بعد الاعتماد يُحدّث prompt الجدولة ليقرأ هذا الملف بدل M1 ويحدد نطاق M2-01؛
Codex كل15دقيقة وWorkBuddy حسب الجدولة التي يثبتها فعلًا. لا يعد وجود MD
تشغيلًا للعامل، ولا نعيد مهمة مكتملة لإبقاء الجدولة مشغولة.
