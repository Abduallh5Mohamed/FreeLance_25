## Behavior before → after

1. `handleApproveRequest` (`src/pages/Fees.tsx`)
   - Before: after `approveSubscriptionRequest` succeeded, a rejecting
     `loadFeesFromDB` fell into the same catch as the mutation and showed the
     destructive "خطأ / فشل في قبول الطلب" toast without closing the dialog.
   - After: the mutation is isolated; only a real approval rejection is a write
     failure. A confirmed approval whose list refresh throws now shows the
     non-destructive "✅ تم قبول الطلب" toast with
     "تعذر تحديث القائمة؛ ستظهر البيانات عند إعادة التحميل", closes the dialog and
     clears the selection. The mutation is not retried and the stale fee list is
     not written into state.
2. `handleDeleteFee` (`src/pages/Fees.tsx`)
   - Before: after `deleteFee` succeeded, a rejecting `loadFeesFromDB` produced
     the destructive "خطأ / فشل في حذف العملية" toast.
   - After: only a real deletion rejection is a write failure. A confirmed
     deletion whose list refresh throws now shows the non-destructive
     "تم الحذف بنجاح" toast with the same refresh warning. The mutation is not
     retried and the stale fee list is not written into state.
3. `src/tests/fees-page-workflow.test.ts`
   - The harness now captures the REAL approve/delete bindings rendered by the
     component (not injected seams) and drives them with a real `confirm` shim
     for delete.
   - Added coverage for approve and delete with failed `getFees`: exactly one
     mutation, exactly one refresh attempt (two list reads), success-with-
     refresh-warning toast, no destructive toast, zero fee-list setter calls;
     approve also asserted to close the dialog and clear selection.
   - Added successful approve/delete refresh cases and rejected mutation cases
     (one mutation, no refresh, destructive failure toast, no list update).

## Preserved behavior
